# Release Stages and Readiness

## R1 — Interactive Prototype
Purpose: validate interface concepts, navigation, and user journeys through a clickable prototype.

Acceptance focus:
- Core agreed journeys are navigable.
- Interface behavior and responsive layouts are reviewable.
- Feedback from internal and external validation is captured.
- Known limitations and deferred scope are visible.

## R2 — Working Software Demo
Purpose: progressively turn selected journeys into functional software.
- Begin with fictional simulated data.
- Integrate selected frontend/backend workflows end-to-end as they are ready.
- Demonstrate validation, persistence, and role-aware behavior where in scope.
- Clearly label the environment as a non-production demo.

## R3 — Controlled Pilot
Purpose: supervised limited deployment.
- Begin with simulated institutional/student data.
- Real data requires institutional, legal, privacy, and security approvals.
- Define pilot participants, operating procedures, support, incident handling, and exit criteria before launch.

## R4 — Production MVP
Requires approved functional scope, security and privacy controls, tested workflows, operational readiness, backup/recovery, support, and release verification.

## R5 — Commercial General Availability
Requires repeatable onboarding, support, SaaS operations, and approved processes for dedicated deployments where applicable.

## Progression
Each stage needs explicit entry, exit, and acceptance criteria. Progress is readiness-based; no calendar deadline is imposed. Passing one stage does not automatically establish readiness for the next.
